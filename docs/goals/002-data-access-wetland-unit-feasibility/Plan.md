# Plan

## Purpose

Convert the foundation documents into a current-source feasibility decision
package for data access and wetland-unit design.

## Expected File Responsibilities

- `docs/source_evidence_register.md`: source-backed evidence table for current
  data and access claims.
- `docs/data_access_feasibility.md`: feasibility memo for each candidate data
  stream.
- `docs/wetland_unit_feasibility.md`: comparison of spatial support options.
- `docs/prototype_scope.md`: recommended smallest defensible prototype.
- `docs/decision_memo_002.md`: supervisor-facing recommendation and next step.
- `docs/data_stream_register.md`: updated status and next actions.
- `docs/decision_log.md`: decisions made or deferred.
- `docs/goals/002-data-access-wetland-unit-feasibility/Log.md`: execution log.

## Task Sequence

1. Confirm repo state and read the Goal 001 foundation docs.
2. Identify official/primary sources to inspect for each data stream and
   wetland-unit option.
3. Build the source evidence register first.
4. Draft the data-access feasibility memo from the evidence register.
5. Draft the wetland-unit feasibility memo, including uncertainty and validation
   implications.
6. Recommend the smallest prototype in `docs/prototype_scope.md`.
7. Write the supervisor decision memo and update existing registers/logs.
8. Validate links, source coverage, Git hygiene, and absence of data files.
9. Commit and push if validation passes.

## Self-Review Questions

- Are current-source claims backed by official URLs and access dates?
- Did the goal avoid downloading or requesting data?
- Does the wetland-unit recommendation preserve hydrology, biodiversity
  alignment, interpretability, and uncertainty?
- Does the prototype recommendation make Goal 003 smaller and executable?
- Are unresolved permission questions explicit rather than papered over?
